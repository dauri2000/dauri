# Revisión individual del stronghold y el End

**No está certificado todavía un combate completo sin fallos.** Se revisaron las 246 filas del catálogo una por una y se vinculó cada una a un resultado concreto de código, mapping o prueba controlada. Ninguna fila se presenta como una prueba realizada dentro del servidor.

## Qué se comprobó realmente

- Mappings: 739 estados de 89 identificadores pasan conversión con runtime IDs secuenciales y hash; 6058 afirmaciones son controles de datos/serialización, no 6058 mecánicas jugadas.
- Entidades: 58 afirmaciones sobre clases reales; 53 conversiones/modelos y 5 reproducciones de riesgos/huecos. Incluye barra de jefe, cristal base/haz, seis caras de shulker, apertura, owner UID, efectos y proxies HITBOX suministrados.
- Segunda pasada de entidades: 13 afirmaciones adicionales, 4 de biblioteca/apariencia y 9 de gates/mensajes/estado. Sin HITBOX recibido no se inventan partes; la lista vacía conserva selección vanilla. Recursos estándar reproducen fallback Java de dragón y Enderman.
- Objetos: 8 pruebas focalizadas de helpers reales: Use/StartUsingItem, restricciones de mano, cohete en planeo/suelo, chargedItem, FireworkData y cooldown. No prueban acierto ni aceptación de servidor.
- Mundo: 8 comprobaciones de solo lectura, incluidas 2 que confirman el hueco de chorus; gateway conserva Age y ExitPortal. No se recorrió un portal.
- Los conteos se solapan en recursos y fronteras; no se suman como una puntuación global.
- Las tres correcciones IF48 reúnen 60 grupos de comprobación: 18 del arco, 21 de chorus y 21 de créditos. Son controles de sus métodos/rutas concretos; no una certificación del End completo.

Base estable: IF46, SHA256 `a0d21a7476ccd2c4ebf5570efd8c3474ae3ea66015c84054c0040532faf57ea8`. IF47 añade diagnóstico XP. Los informes fijan los hashes realmente ensayados. Fuentes oficiales de catálogo: Bedrock 1.26.50.4 fijada a commit; etiqueta objetivo del puente 1.26.51, versión del servidor real aún sin confirmar. Las 20 paletas de ciudad Java 26.3 solo ayudan a enumerar materiales, no validan generación Bedrock.

Cada tabla mantiene el ID del catálogo original. «Mapeo comprobado» significa conversión de estado/ítem; «helper probado» significa ejecución del método con transporte/registro de prueba; «ruta revisada» significa inspección concreta. La última columna identifica el resultado que todavía necesita una sesión real. Las referencias completas quedan en el JSON.
