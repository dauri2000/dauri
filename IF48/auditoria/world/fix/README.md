# IF48 chorus connection projection

The delivered native chorus plant has no six-direction connection properties. Its Java projection uses all-false arms, and ConnectedBlockShapes excludes it. This leaves no reconstruction path for a complete received tree.

Production scope is exactly two classes: replace `ConnectedBlockShapes.class` with two additive guards, and add package-private `ChorusPlantConnections.class`. The first guard includes only the exact vanilla identifier in the existing candidate paths. The second reconstructs the Java blockstate from six received neighboring cells. Every original instruction is retained behind the guards and canonical reversal reproduces IF46 exactly. Full core, helper and target are not recompiled.

The helper only selects among existing Java chorus states. It never changes native palettes, growth, mining, drops, item stacks, fluid state, predictions, ACKs or packets to the server. All six directions connect to vanilla stem/flower; lower end stone connects down, matching canonical historical Java projection. Unknown neighbors and other namespaces remain disconnected. This is an adapter representation rule, not a claim to execute vanilla BDS collision. PMMP's third-party native all-side endstone connectivity differs and is explicitly documented in `../reference/source-manifest.json`.

The class hashes are frozen in `candidate-class-hashes.json`. Independent review in `../independent` passes 8 additional targeted groups including 120 nonchorus differential controls with identical output. Total 21 directed groups; grouped 64 masks and 120 controls are not counted again.

Validation: same corrected-behavior regression fails IF46 at candidate routing. Patched classes pass 13 targeted tests, with all64 registered Java connection masks in one case. Actual ChunkTracker methods execute for getJavaBlockState, initial remapChunk, neighbor removal/update, loaded border refresh, missing neighbor chunks and vertical section boundaries. Minimal registry bootstrap, supplied native palette/session and transport capture are explicit test boundaries; Unsafe allocation appears only in test source. No Minecraft render, Mixin engine, live BDS, growth or native server collision executes.
